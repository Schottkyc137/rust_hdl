## Project Overview

**rust_hdl** is a fast VHDL language server and analysis library written in Rust. It provides a Language Server Protocol (LSP) implementation for VHDL with semantic analysis, completions, go-to-definition, renaming, and more.

## Common Commands

```bash
# Build all default workspace members
cargo build

# Build a specific crate in release mode
cargo build -p vhdl_lang --release
cargo build -p vhdl_ls --release

# Run all tests
cargo test

# Run tests for a specific crate
cargo test -p vhdl_lang
cargo test -p vhdl_syntax

# Run a single test by name
cargo test -p vhdl_lang test_name_here

# Check formatting
cargo fmt -- --check

# Auto-format
cargo fmt

# Lint (CI uses -D warnings to fail on all warnings)
cargo clippy --all-targets --all-features -- -D warnings

# Clippy for a specific crate
cargo clippy -p vhdl_lang --all-targets --all-features -- -D warnings

# Regenerate AST node code for vhdl_syntax
cargo xtask codegen

# Check that generated files are up-to-date (used in CI)
cargo xtask codegen --check
```

## Workspace Structure

The workspace is defined in the root `Cargo.toml`. All dependency versions are centralized there and shared across crates. The `rust-version` is 1.87.

| Crate | Purpose |
|-------|---------|
| `vhdl_lang` | Core VHDL frontend: parsing, semantic analysis, completions, formatting |
| `vhdl_ls` | LSP server built on top of `vhdl_lang` |
| `vhdl_lang_macros` | Proc-macro crate used by `vhdl_lang` |
| `vhdl_syntax` | **Early stage** — new standalone syntax library (tokenizer + parser + AST) |
| `xtask` | Dev-tool (xtask pattern) — code generator for `vhdl_syntax`'s AST node definitions |
| `vhdl-dump-ast` | CLI utility to dump VHDL AST as JSON/YAML using `vhdl_syntax` |

## Architecture

### vhdl_lang (Core)

The library is split into two independent phases:

1. **Parsing** (`ast/`, `ast.rs`) — produces an AST that includes comments and trivia, enabling formatting even on syntactically incorrect code.
2. **Semantic Analysis** (`analysis/`) — runs after parsing; resolves names, checks types, computes compilation order automatically.

Key modules:
- `analysis/` — 25+ files handling semantic analysis (name resolution, type checking, etc.)
- `ast.rs` — central AST structure definitions
- `named_entity/` — symbol table and entity tracking
- `completion/` — LSP code completion logic
- `formatting/` — code formatter (works on parse trees, independent of analysis)
- `lint/` — diagnostic/lint rules
- `config.rs` — parses `vhdl_ls.toml` project configuration
- `project.rs` — manages multi-file VHDL projects and library mappings

### vhdl_ls (Language Server)

Thin LSP wrapper over `vhdl_lang`. Handles:
- LSP protocol via `lsp-server` and `lsp-types`
- stdio transport (`stdio_server.rs`)
- RPC channel (`rpc_channel.rs`)
- LSP request/notification dispatch (`vhdl_server/`)

### vhdl_syntax (Early Stage)

A separate, newer approach to VHDL parsing with a different design philosophy. **API is unstable — not for production use.** The AST node definitions in `src/syntax/generated/` are auto-generated by the `xtask` crate. To regenerate:

```bash
cargo xtask codegen
# Files are written directly to vhdl_syntax/src/syntax/generated/

# Verify generated files are up-to-date (also runs in CI):
cargo xtask codegen --check
```

Key differences from `vhdl_lang`:
- Preserves all trivia (whitespace, comments) as leading trivia on tokens
- Supports multiple VHDL standards (2002, 2008, 2019) via `standard.rs`
- Designed for AST rewriting and source transformation

## VHDL Standards

Both `vhdl_lang` and `vhdl_syntax` support VHDL 2002, 2008, and 2019. The default standard is configurable per-library in `vhdl_ls.toml`.

## Character Encoding

VHDL source files use ISO-8859-1 (Latin-1). The `latin_1.rs` module in `vhdl_syntax` handles this. AST dumps and internal strings use UTF-8.

## CI Quality Gates

The CI (`.github/workflows/build-test-all.yml`) enforces on every PR:
- `cargo fmt -- --check`
- `cargo clippy --all-targets --all-features -- -D warnings`
- Tests pass on Linux (GNU + musl), Windows (MSVC), and macOS (aarch64)
- `cargo xtask codegen --check` — verifies committed generated files match what `xtask` would produce

The `clippy.toml` suppresses the interior-mutability lint for `vhdl_lang::data::source::UniqueSource`.
